Each market uses one ERC-20 as collateral. The market and both pools account in units of that token.

## Assumptions

The factory only checks that the collateral address is nonzero. Documented assumptions are stronger: transfers should be non-reentrant, and sender/receiver balances should change by exactly the requested amount. Passing the factory check does **not** mean the token is safe.

| Collateral form | Core pool units | Router units |
| --- | --- | --- |
| Plain ERC-20 | The collateral token | The collateral token |
| ERC-4626 vault share | The vault share token | The vault's underlying token |

The core does not track a separate underlying price for ERC-4626 collateral. It accounts only for the vault shares held by the market.

## Reconciliation

On settlement (pool writes and fee sweeps), the market reconciles `collateral.balanceOf(market)` against internal accounting before collateral fees, funding, and price PnL.

1. Reserve recorded `protocolFees` (capped to actual balance if needed)
2. Compare remainder to `receiverPool + payerPool`
3. Allocate surplus/deficit pro rata (rounding from the larger pool first)
4. If both pools are empty, leftover → `protocolFees`

This captures donations and rebases in accounting. It does not make fee-on-transfer tokens safe.

## Deposit and withdraw units

Core pools always take and return **market collateral**. If the collateral is an ERC-4626 vault share, direct pool callers use vault-share units.

For each deposit or redemption, a router probes `asset()` on `market.collateral()`. If that call succeeds, the router treats the collateral as ERC-4626:

1. **Deposit:** pull underlying → deposit into vault → deposit vault shares into Null pool
2. **Redeem:** redeem Null shares → redeem vault → send underlying

Router asset amounts and minimum-asset checks are in **underlying** units for ERC-4626 collateral, and in collateral units for a plain ERC-20. If `asset()` reverts, the router treats the token as a plain ERC-20. A successful `asset()` probe is only detection; malformed vault behavior can still make wrapping or unwrapping revert.

## ERC-4626 collateral example

Do not assume that an ERC-4626 vault share and its underlying asset use the same decimals. Read both from the Ethereum mainnet contracts, then convert each human-readable amount in the units expected by the call:

```ts
import {
  parseAbi,
  parseUnits,
  type Address,
  type PublicClient,
} from "viem";

const vaultAbi = parseAbi([
  "function asset() view returns (address)",
  "function decimals() view returns (uint8)",
]);
const erc20Abi = parseAbi(["function decimals() view returns (uint8)"]);

interface GetCollateralUnitsConfig {
  publicClient: PublicClient;
  collateral: Address;
  shareAmount: string;
  underlyingAmount: string;
}

export async function getCollateralUnits({
  publicClient,
  collateral,
  shareAmount,
  underlyingAmount,
}: GetCollateralUnitsConfig) {
  const [asset, shareDecimals] = await Promise.all([
    publicClient.readContract({
      address: collateral,
      abi: vaultAbi,
      functionName: "asset",
    }),
    publicClient.readContract({
      address: collateral,
      abi: vaultAbi,
      functionName: "decimals",
    }),
  ]);
  const assetDecimals = await publicClient.readContract({
    address: asset,
    abi: erc20Abi,
    functionName: "decimals",
  });

  return {
    asset,
    directPoolAssets: parseUnits(shareAmount, shareDecimals),
    routerAssets: parseUnits(underlyingAmount, assetDecimals),
  };
}
```

For a direct Receiver or Payer pool deposit, approve the pool to spend the vault share token and pass `directPoolAssets`. For `router.depositMarket`, approve the router to spend the returned `asset` and pass `routerAssets`. These values represent independently chosen share and underlying amounts; they are not interchangeable. The vault exchange rate determines how many shares an underlying deposit receives, so use `previewDeposit` or `convertToShares` when you need an estimate and apply an appropriate slippage bound.

<Note>
Null Receiver/Payer shares are themselves ERC-4626. That is separate from using an ERC-4626 vault as **market collateral**.
</Note>

## Selection risks

Avoid or carefully review tokens that rebase, charge transfer fees, blacklist, hook transfers, or depend on external strategies with admin controls.
