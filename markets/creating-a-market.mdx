Every Null V1 market is defined by a unique combination of three immutable parameters: a collateral asset, a price oracle, and a funding multiplier (`mu`). This triplet acts as the market's identity — if a market for a given `(asset, oracle, mu)` tuple already exists, no duplicate can be created. Once deployed, a market is permanent and permissionless: anyone can interact with it, and its core parameters can never be changed. Before creating a market, you should verify no matching market exists, choose your parameters deliberately, and use the router to handle oracle update data in a single transaction.

## Prerequisites

Before you create a market, make sure you have the following:

- The address of the deployed `NullV1Factory`
- The address of the deployed `NullV1Router`
- An ERC-20 collateral token address (`asset`)
- A compatible `INullV1Oracle` implementation address (`oracle`)
- A chosen `mu` value in parts-per-million (ppm) — see [Market Parameters](/markets/market-parameters) for guidance

---

## How Markets Are Identified

Markets are keyed by the tuple `(asset, oracle, mu)`. You can query the factory directly to check whether a market already exists for your chosen parameters before attempting to create one.

<Note>
  The factory will revert with `MarketExists(asset, oracle, mu)` if you try to
  create a duplicate. Always call `getMarket` first to avoid wasted gas.
</Note>

```solidity
// Check whether a market already exists for this parameter tuple
address existing = factory.getMarket(asset, oracle, mu);

if (existing != address(0)) {
    // Market already deployed — use it directly
    INullV1Market market = INullV1Market(existing);
}
```

## Creation Steps

<Steps>
  <Step title="Choose your asset, oracle, and mu">
    Select the ERC-20 collateral token your market will use, the oracle that
    will price the underlying, and the `mu` funding multiplier. These three
    values are **permanent** — they cannot be updated after deployment. Refer to
    [Market Parameters](/markets/market-parameters) for help choosing `mu` and
    [Collateral](/markets/collateral) for supported asset types.
  </Step>

  <Step title="Check the market does not already exist">
    Call `factory.getMarket(asset, oracle, mu)` on-chain. If the return value is
    `address(0)`, the market has not been created yet and you can proceed. If it
    returns a non-zero address, use that existing market instead.

    ```solidity
    address existing = factory.getMarket(asset, oracle, mu);
    require(existing == address(0), "Market already deployed");
    ```
  </Step>

  <Step title="Create the market via the router">
    Call `router.createMarket(...)` rather than calling the factory directly.
    The router accepts `updateData` (oracle price payloads) and forwards them to
    the oracle in the same transaction, ensuring the oracle's price is fresh when
    the market is initialised. For static oracles such as Uniswap V3 TWAP or
    Base Fee, pass an empty `updateData` array.

    <CodeGroup>
      ```solidity Solidity
      import {INullV1Router} from "nullv1/interfaces/INullV1Router.sol";
      import {IERC20} from "openzeppelin/token/ERC20/IERC20.sol";
      import {INullV1Oracle} from "nullv1/interfaces/INullV1Oracle.sol";

      // Pyth oracle example — supply updateData fetched off-chain
      bytes[] memory updateData = new bytes[](1);
      updateData[0] = pythPayload; // bytes from Pyth Hermes API

      INullV1Market market = router.createMarket(
          factory,   // INullV1Factory
          asset,     // IERC20 collateral token
          oracle,    // INullV1Oracle implementation
          10_000,    // mu = 1% in ppm (good for single-stock RWAs)
          updateData
      );

      address receiverPool = address(market.receiverPool());
      address payerPool    = address(market.payerPool());
      ```

      ```typescript TypeScript (viem)
      import { encodeFunctionData, parseAbi } from "viem";

      const routerAbi = parseAbi([
        "function createMarket(address factory, address asset, address oracle, uint24 mu, bytes[] calldata updateData) returns (address market)",
      ]);

      // For pull-based oracles: fetch updateData from Pyth Hermes
      const hermesRes = await fetch(
        `https://hermes.pyth.network/api/latest_vaas?ids[]=${priceId}`
      );
      const { binary } = await hermesRes.json();
      const updateData = binary.data.map((d: string) => `0x${d}`);

      const hash = await walletClient.writeContract({
        address: ROUTER_ADDRESS,
        abi: routerAbi,
        functionName: "createMarket",
        args: [FACTORY_ADDRESS, ASSET_ADDRESS, ORACLE_ADDRESS, 10_000, updateData],
      });

      const receipt = await publicClient.waitForTransactionReceipt({ hash });
      // Parse the MarketCreated event from receipt.logs to get market address
      ```
    </CodeGroup>
  </Step>

  <Step title="Record the emitted addresses">
    The factory emits `MarketCreated` when the market is deployed. This event
    contains all the addresses you need to interact with the market.

    ```solidity
    event MarketCreated(
        address indexed asset,
        address indexed oracle,
        uint24  indexed mu,
        address market,
        address receiverPool,
        address payerPool
    );
    ```

    Parse this event from the transaction receipt to retrieve the `market`,
    `receiverPool`, and `payerPool` addresses. You can also retrieve them at any
    time by calling the read-only `factory.getMarket(asset, oracle, mu)` and then
    reading `market.receiverPool()` and `market.payerPool()`.
  </Step>
</Steps>

## Error Reference

Understanding the revert errors from the factory helps you handle failures gracefully.

| Error | Cause | Resolution |
|---|---|---|
| `MarketExists(asset, oracle, mu)` | A market for this tuple already exists | Call `getMarket` first; use the existing market |
| `ZeroAsset()` | The `asset` address is `address(0)` | Provide a valid ERC-20 token address |
| `ZeroOracle()` | The `oracle` address is `address(0)` | Provide a deployed `INullV1Oracle` address |
| `InvalidMu(mu)` | `mu` is zero | Choose a non-zero `mu` value in ppm |

<Warning>
  The `mu` parameter is immutable. If you deploy a market with the wrong `mu`,
  you cannot update it. You must deploy a new market with a different `mu`. Plan
  your parameterization carefully before calling `createMarket`.
</Warning>

## Direct Factory vs. Router

You can call `factory.createMarket(asset, oracle, mu)` directly, but this approach does **not** update the oracle price before initialization. For updatable oracles, prefer the router so that the oracle price is current at the moment of market creation. For purely on-chain oracles such as Uniswap V3 TWAP or Base Fee, both paths are equivalent.

<Tip>
  Use the router for market creation when the oracle accepts `updateData`. The
  current router pays update fees from its own ETH balance, so make sure the
  deployed router is funded before relying on fee-charging oracle updates.
</Tip>
