Oracles supply the normalized price used when a Null V1 market settles. The
supported implementations are all pull-based:

- Pyth
- Chainlink Data Streams V3 for crypto
- Chainlink Data Streams V11 for RWA/session feeds

## The Price Scale

All supported oracles return the price of one base asset in quote-asset units
scaled by `1e36`.

```solidity
uint256 price = oracle.price(); // 200 * 10^36 means 200 quote units
```

## Update flow

Fetch a signed payload from the relevant provider and pass it as `updateData`
to router market creation, deposit, or redemption. If the array is nonempty,
the router updates the oracle before the market operation.

```solidity
router.createMarket(factory, collateral, oracle, frm, updateData);
router.depositMarket(
    market,
    receiverAssets,
    payerAssets,
    minReceiverShares,
    minPayerShares,
    deadline,
    updateData
);
```

### Pyth

`NullV1PythOracle.update` is payable. `NullV1PayableRouter` calculates the Pyth
fee and forwards it from the router's pre-funded ETH balance. The caller does
not attach the update fee to the market-operation call.

### Chainlink V3 and V11

Both Chainlink contracts implement nonpayable `update`, and
`getUpdateFee(updateData)` always returns zero. Use `NullV1Router`, which calls
the oracle without forwarding native currency.

<Warning>
  The router type is part of the integration. The fee-less router cannot pay a
  Pyth update fee.
</Warning>

## Freshness and the 10-day escape

All three implementations use a 60-second normal freshness threshold. Their
read path behaves as follows:

- up to 60 seconds in the future: accepted
- more than 60 seconds in the future: `StalePrice()` revert
- up to 60 seconds old: accepted
- more than 60 seconds but less than 10 days old: `StalePrice()` revert
- exactly 10 days old or older: last stored positive price is returned

The escape is implemented by each oracle's `price()` function. It is not a
separate redemption mode, and it does not update the stored price.

Update acceptance is narrower: Pyth and Chainlink V3 reject future timestamps;
Chainlink V11 accepts a report up to 60 seconds ahead. All three reject updates
that are more than 60 seconds old.

<Warning>
  The 10-day path deliberately permits an old price so settlement can resume
  after a prolonged upstream outage. Treat the market as degraded and account
  for the stale-price risk.
</Warning>

For exact report checks and creation parameters, see
[Pyth](/contracts/oracles/pyth) and
[Chainlink Data Streams](/contracts/oracles/chainlink).
