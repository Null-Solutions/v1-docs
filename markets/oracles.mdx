Spot settlement reads one oracle, stored on the market for its lifetime. The price is scaled to `1e36`.

Supported market oracles are Chainlink Data Streams clones:

| Oracle | Feeds | Router |
| --- | --- | --- |
| `NullV1ChainlinkOracleV3` | One 24/7 report | `NullV1Router` |
| `NullV1ChainlinkOracleV11` | Regular, extended, and overnight session reports | `NullV1Router` |

The router calls `update(bytes[])` before `price()`. Chainlink's `getUpdateFee` on this integration is zero. Do not send ETH with `depositMarket` or `redeemMarket`. The router does not create markets: for market creation, call `oracle.update(updateData)` yourself and then the factory. See [Creating a market](/markets/creating-a-market).

## Update flow

1. Read `oracle.priceId()` (V11: the feed for the current session).
2. Fetch the signed report from Chainlink Data Streams.
3. Pass that payload as `updateData`. Use `[]` only when the stored price is still inside the oracle's freshness window.
4. Submit through `NullV1Router`.

Never fabricate report bytes. If `price()` reverts, the market action reverts with it.

## Freshness

Each oracle enforces its own timestamp window inside `update` and `price`. The window is set when the oracle is created: read `maxValidFromAge()` and `maxValidFromFutureSkew()` (seconds) from the oracle. A stale report does not settle. Both oracle types can accept a report slightly ahead of chain time, up to `maxValidFromFutureSkew`. That does not refresh a stored price by itself. You still submit the report.

If no report is stored for 15 days, the oracle serves the last stored price for good and ignores later reports. See [Chainlink](/contracts/oracles/chainlink#staleness-and-escape-behavior).

Margin books use a different oracle, built on pool previews. See [Morpho oracles](/contracts/oracles/morpho).
