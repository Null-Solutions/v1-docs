## Terms to preserve

| Term | Meaning |
| --- | --- |
| **Receiver** | Pool that receives positive reference-asset returns; other side of signed funding |
| **Payer** | Pool that backs Receiver; opposite price risk; other side of funding |
| **Coverage `P/R`** | Payer assets ÷ Receiver assets |
| **Payer instantaneous leverage `L = R/P`** | Receiver assets ÷ Payer assets at that market state; inverse of coverage |
| **FRM** | Immutable funding-rate model dependency |
| **Funding** | Signed transfer between pools; positive `f` ⇒ Receiver pays Payer |
| **Price settlement** | Value transfer from oracle price movement |
| **Solvency bound** | Cap on net funding+price debit at `max(pool − MIN_POOL_ASSETS, 0)` |
| **Mint / Burn (app)** | Product copy for deposit / redeem |

## Guardrails for generated code

- Discover markets by `(collateral, oracle, frm)` — do not invent pool addresses
- Read pool addresses from the market or `CreateMarket`
- Keep the ratios distinct: coverage is `P/R`; `L = R/P` is the leverage Payer has at that market state, not a funding rate
- Handle zero denominators explicitly; do not report either ratio as finite when its denominator is zero
- Treat shares as ERC-4626; share decimals = collateral decimals + 10
- Assume every pool write settles the market first
- Always pass slippage mins and deadlines on router calls
- Match router to oracle: Chainlink → fee-less; Pyth → payable (no `msg.value` from user)
- Convert units when collateral is ERC-4626 (router = underlying; pool preview = vault shares)
- Fetch signed oracle payloads from the documented provider flow; never fabricate `updateData`
- Do not invent a Null SDK, REST trading API, Ethereum addresses, deployment blocks, collateral, markets, or oracles
- Copy canonical Ethereum constants from [Ethereum deployments](/resources/addresses) once published; until then, require typed configuration inputs

## What not to invent

Null is contracts-first. There is no published partner API with API keys, no order book, and no liquidation engine. Gains move only from collateral already in the market.

Do not infer contract-level whitelist behavior from hosted-app access controls. Product approval requirements do not establish a contract whitelist policy.
