Each market has two `NullV1Pool` contracts: Receiver and Payer. Both implement ERC-4626. A share is a proportional claim on one pool's market-recorded collateral, not a position with a private entry price.

## Discover and name pools

Read `receiverPool()` and `payerPool()` from the market or index the factory's `CreateMarket` event. Do not derive or hardcode pool addresses.

```solidity
enum NullV1PoolKind { Receiver, Payer }

function poolKind() external view returns (NullV1PoolKind);
function market() external view returns (INullV1Market);
```

Pool token metadata comes from the oracle's base metadata:

| Kind     | Token name                  | Symbol          |
| -------- | --------------------------- | --------------- |
| Receiver | `<baseName> Receiver Share` | `r<baseSymbol>` |
| Payer    | `<baseName> Payer Share`    | `p<baseSymbol>` |

Empty base metadata falls back to `Base` and `BASE`. Treat `name()` and `symbol()` as display labels. Use `poolKind()` or the market's pool addresses to determine the side.

## Source of truth

```solidity
function totalAssets() public view returns (uint256);
```

`totalAssets()` returns the selected pool's amount from the market's last settled state. It is denominated in **market collateral units** and does not settle the market.

The pool's ERC-4626 `asset()` is always `market.collateral()`. If that collateral is itself an ERC-4626 vault, pool assets are `collateralVault` shares, not the vault's `underlying`.

Share decimals are `collateral.decimals() + 10`. Conversion math also includes OpenZeppelin's virtual shares. Always read `decimals()` and use ERC-4626 conversion functions instead of assuming a fixed asset-to-share scale.

## Settlement before writes

Every state-changing ERC-4626 entry point settles the market before converting between assets and shares:

| Function                            | Caller specifies                  | Result          |
| ----------------------------------- | --------------------------------- | --------------- |
| `deposit(assets, receiver)`         | Exact market-collateral assets in | Shares minted   |
| `mint(shares, receiver)`            | Exact shares out                  | Assets charged  |
| `withdraw(assets, receiver, owner)` | Exact assets out                  | Shares burned   |
| `redeem(shares, receiver, owner)`   | Exact shares in                   | Assets returned |

Execution uses the post-settlement pool value. A prior pool preview can differ materially.

## Preview and fee formulas

| Function                  | Fee pattern  |
| ------------------------- | ------------ |
| `previewDeposit(assets)`  | Fee-on-total |
| `previewMint(shares)`     | Fee-on-raw   |
| `previewWithdraw(assets)` | Fee-on-raw   |
| `previewRedeem(shares)`   | Fee-on-total |

In practical terms:

- `deposit`: the supplied assets include the entry fee; only the net amount mints shares.
- `mint`: the caller pays the raw asset quote plus the entry fee.
- `withdraw`: the pool deducts the requested assets plus the exit fee.
- `redeem`: the exit fee is deducted from the gross asset quote.

The previews use the last settled state. Funding, price PnL, collateral fees, balance reconciliation, or other transactions can move the execution rate. Use `NullV1Lens.previewMarket` for a settlement projection and a router minimum for execution protection.

Fees leave the Receiver/Payer system into market `protocolFees`. See [Fees](/developers/fees).

<Warning>
`maxDeposit` and `maxMint` always return `type(uint256).max` — never use them to size inputs. `maxWithdraw` is net of the exit fee but reads the last settled state, so a full exit via `withdraw(maxWithdraw(owner))` can revert once execution settles the market. Exit fully with `redeem(balanceOf(owner))` instead. See [Max functions](/contracts/pool#max-functions).
</Warning>

## Unit pipelines

Direct pool calls:

```text
market collateral ↔ Null pool shares
```

Router calls with plain ERC-20 collateral:

```text
market collateral ↔ Null pool shares
```

Router calls when market collateral exposes `asset()`:

```text
vault underlying ↔ market collateral vault shares ↔ Null pool shares
```

Use generic names for that final pipeline:

```text
underlying ↔ collateralVault shares ↔ Receiver or Payer pool shares
```

## Position value

```text
positionAssets ≈ convertToAssets(balanceOf(user))
```

Use `convertToAssets` or `previewRedeem` rather than a custom division. `previewRedeem` also applies the exit fee. Both are snapshots of the last settled state.

## Direct pool vs router

| Prefer direct pool when              | Prefer router when                  |
| ------------------------------------ | ----------------------------------- |
| User already holds market collateral | Combined Receiver + Payer in one tx |
| Single-side action only              | Deadlines and slippage minimums     |
| You manage oracle freshness yourself | Push-oracle `updateData`            |
|                                      | ERC-4626 collateral wrap / unwrap   |
