Depositing into a Null V1 market means supplying collateral to the receiver pool, the payer pool, or both simultaneously. Use `NullV1Router` for fee-less Chainlink updates and `NullV1PayableRouter` for native-fee Pyth updates. Both support combined deposits, ERC-4626 collateral wrapping, slippage minimums, and transaction deadlines. You can also interact with each `NullV1Pool` directly through ERC-4626.

## Receiver pool vs. payer pool

Each market exposes two independent ERC-4626 pools. When you call `router.depositMarket`, you specify how many assets to deposit into each:

| Parameter | Pool | Effect |
|---|---|---|
| `receiverAssets` | Receiver pool | Mints receiver shares proportional to your deposit |
| `payerAssets` | Payer pool | Mints payer shares proportional to your deposit |

Set either value to `0` to skip that pool entirely. For example, to deposit only into the receiver pool, pass `payerAssets = 0` and `minPayerShares = 0`.

## Previewing shares before you deposit

Before sending a deposit transaction, call `previewDeposit` on the target pool to estimate how many shares you will receive. The preview accounts for the entry fee but uses the market's last settled state. Execution settles first, so elapsed funding, price PnL, collateral fees, or balance reconciliation can change the result even when no earlier user transaction lands.

```ts
const receiverPool = new ethers.Contract(receiverPoolAddress, nullV1PoolAbi, provider);
const payerPool    = new ethers.Contract(payerPoolAddress,    nullV1PoolAbi, provider);

// Get share estimates inclusive of entry fee deduction
const estimatedReceiverShares = await receiverPool.previewDeposit(receiverAssets);
const estimatedPayerShares    = await payerPool.previewDeposit(payerAssets);
```

<Note>
`previewDeposit` reflects the entry fee. For ERC-4626 collateral, router amounts are underlying units while pool previews expect collateral-vault share units. Quote the vault wrapping conversion before calling the pool preview. See [Fees](/fees) for current fee values.
</Note>

## Slippage protection

The router rejects the transaction if the shares it would mint fall below your specified minimums. This protects you from adverse price movements between your simulation and the on-chain execution.

```ts
const slippageBps = 50n; // 0.5% tolerance
const minReceiverShares = estimatedReceiverShares * (10_000n - slippageBps) / 10_000n;
const minPayerShares    = estimatedPayerShares    * (10_000n - slippageBps) / 10_000n;
```

If slippage is exceeded the router reverts with a typed error:

- `SlippageReceiverShares(expected, actual)` — the receiver pool would have minted fewer shares than `minReceiverShares`.
- `SlippagePayerShares(expected, actual)` — the payer pool would have minted fewer shares than `minPayerShares`.

<Warning>
Setting `minReceiverShares = 0` or `minPayerShares = 0` disables slippage protection for that pool. Only do this in test environments or when you fully trust that no competing transactions will affect the pool ratio.
</Warning>

## Deadline

The `deadline` parameter is a Unix timestamp (in seconds). If the transaction is included in a block whose `block.timestamp` exceeds this value, the router reverts with `TransactionTooOld(deadline)`. This prevents your transaction from being held in the mempool and executed at a stale price.

```ts
// Expire after 5 minutes
const deadline = BigInt(Math.floor(Date.now() / 1000) + 5 * 60);
```

## Oracle update data

Supported markets use pull-based oracles. Pass a fresh signed payload as `updateData` when the oracle needs updating, or an empty array only when its stored price is already usable.

```ts
// Already-fresh stored price — skip update
const updateData = [];

// Push oracle (e.g. Pyth) — fetch a fresh price attestation
const updateData = await pythConnection.getPriceFeedsUpdateData([priceFeedId]);
```

<Note>
`NullV1Router` submits fee-less Chainlink updates. `NullV1PayableRouter` pays Pyth update fees from its pre-funded ETH balance and reverts with `InsufficientUpdateFeeBalance(balance, required)` when underfunded.
</Note>

## ERC-4626 collateral through the router

If the market collateral is an ERC-4626 vault share, the router accepts the vault's underlying token and wraps it before depositing into the Null pool. Direct pool calls still use the collateral share itself.

The flow is:

1. You approve the router to spend the underlying token.
2. You call `depositMarket` with underlying-token amounts.
3. The router wraps the underlying into the ERC-4626 collateral token.
4. The router deposits collateral-vault shares into the Receiver and/or Payer pool.

## Full deposit example

<Tabs>
  <Tab title="ethers.js">
```ts
import { ethers } from "ethers";

const provider = new ethers.JsonRpcProvider(RPC_URL);
const signer   = await provider.getSigner();

const router      = new ethers.Contract(ROUTER_ADDRESS,  nullV1RouterAbi, signer);
const receiverPool = new ethers.Contract(RECEIVER_POOL, nullV1PoolAbi,   provider);
const payerPool    = new ethers.Contract(PAYER_POOL,    nullV1PoolAbi,   provider);
const asset        = new ethers.Contract(ASSET_ADDRESS, erc20Abi,        signer);

// Deposit amounts
const receiverAssets = ethers.parseUnits("1000", 6); // 1,000 USDC into receiver
const payerAssets    = ethers.parseUnits("0",    6); // nothing into payer

// Preview and apply 1% slippage tolerance
const expectedShares = await receiverPool.previewDeposit(receiverAssets);
const minReceiverShares = expectedShares * 9900n / 10_000n;
const minPayerShares    = 0n;

// Approve router
await asset.approve(ROUTER_ADDRESS, receiverAssets);

// Set deadline 3 minutes out
const deadline   = BigInt(Math.floor(Date.now() / 1000) + 180);
const updateData = []; // stored oracle price is already fresh

const tx = await router.depositMarket(
  MARKET_ADDRESS,
  receiverAssets,
  payerAssets,
  minReceiverShares,
  minPayerShares,
  deadline,
  updateData
);

const receipt = await tx.wait();
console.log("Deposit confirmed in block", receipt.blockNumber);
```

This example assumes plain ERC-20 collateral. For ERC-4626 collateral, approve
the vault underlying and convert the underlying amount to expected collateral
shares before calling the Null pool's `previewDeposit`.

```solidity
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.24;

import {INullV1Market} from "./interfaces/INullV1Market.sol";
import {INullV1Pool}   from "./interfaces/INullV1Pool.sol";
import {IERC20}        from "@openzeppelin/contracts/token/ERC20/IERC20.sol";

// Minimal local interface shared by NullV1Router and NullV1PayableRouter.
interface INullV1Router {
    function depositMarket(
        INullV1Market market,
        uint256 receiverAssets,
        uint256 payerAssets,
        uint256 minReceiverShares,
        uint256 minPayerShares,
        uint256 deadline,
        bytes[] calldata updateData
    ) external returns (uint256 receiverShares, uint256 payerShares);
}

contract DepositExample {
    INullV1Router public immutable router;

    constructor(address _router) {
        router = INullV1Router(_router);
    }

    function depositReceiverOnly(
        INullV1Market market,
        IERC20 depositToken,
        uint256 receiverAssets,
        uint256 minReceiverShares,
        uint256 deadline,
        bytes[] calldata updateData
    ) external returns (uint256 receiverShares) {
        depositToken.transferFrom(msg.sender, address(this), receiverAssets);
        depositToken.approve(address(router), receiverAssets);

        (receiverShares, ) = router.depositMarket(
            market,
            receiverAssets,
            0,                 // no payer deposit
            minReceiverShares,
            0,                 // no payer minimum
            deadline,
            updateData
        );

        // Transfer shares back to the caller
        INullV1Pool receiverPool = market.receiverPool();
        receiverPool.transfer(msg.sender, receiverShares);
    }
}
```

## Direct ERC-4626 deposit (advanced)

If you want to bypass the router and interact with the pool contract directly, use the standard ERC-4626 `deposit` function. You are responsible for approving the market collateral accepted by the pool and for making sure any push-oracle price has already been updated before the pool action runs.

```ts
const pool  = new ethers.Contract(receiverPoolAddress, nullV1PoolAbi, signer);
const vault = new ethers.Contract(vaultTokenAddress,   erc20Abi,      signer);

// Approve the pool to spend the vault token
await vault.approve(receiverPoolAddress, assets);

// Deposit and receive shares
const shares = await pool.deposit(assets, signerAddress);
```

<Tip>
Use the router for most integrations. Direct ERC-4626 deposits skip slippage enforcement and deadline checks — you must implement those safeguards yourself.
</Tip>
