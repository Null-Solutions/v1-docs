A Null market has two sides: Receiver and Payer. They mirror the two sides of a total return swap, but they are pooled instead of matched one-to-one.

## Market roles at a glance

<img src="/images/diagrams/receiver-payer-flow.png" alt="Chart showing the Receiver and Payer market flow: oracle price updates feed the market, price movement can move value in either direction, and funding flows from Receiver to Payer." />

<Note>
In words: the oracle feeds the market update. Price movement can move value in either direction, but funding always flows from Receiver to Payer.
</Note>

## Receiver

The Receiver pool seeks the return of the reference asset. If the oracle price rises, the Receiver pool receives value from the Payer pool. If the oracle price falls, the Receiver pool pays value to the Payer pool.

Receiver is the synthetic long side of the market. A Receiver does not need to hold the reference asset. The user deposits the market collateral, receives ERC-4626 pool shares, and owns a proportional claim on the Receiver pool.

Receiver also pays funding. Funding is the cost of using Payer collateral as backing capital.

## Payer

The Payer pool supplies the collateral that backs Receiver exposure. If the oracle price rises, Payer pays Receiver. If the oracle price falls, Payer receives value from Receiver.

Payer receives funding for taking this opposite price risk. A Payer can use the position in two ways:

- **Directional Payer:** holds the short exposure and funding stream directly.
- **Hedged Payer:** hedges the short exposure externally and treats the position primarily as a funding trade.

The protocol does not manage the external hedge. It only defines the onchain Payer payoff.

## Shares are pooled claims

Receiver and Payer shares are ERC-4626 compatible vault shares. They are proportional claims on a pool's current value.

If you own 10% of the Receiver pool before an update and no one else enters or exits, you still own 10% of that pool after the update. The value of that 10% changes because the pool value changes.

This differs from a bilateral swap. You do not have a private entry price against a single counterparty. You hold a share of an aggregate pool whose value updates through the market accounting rule.

## Exposure ratio

The most important live market ratio is:

```text
E = Receiver pool value / Payer pool value
```

`E` measures how much Receiver exposure each unit of Payer capital backs.

If the Receiver pool has 1,000 units and the Payer pool has 200 units, then `E = 5`. A 2% move in the reference asset changes Receiver value by about 2%, but it changes Payer value by about 10% before funding and caps, because the same value transfer lands in a smaller pool.

<img src="/images/diagrams/exposure-ratio.png" alt="Bar chart showing an exposure ratio example: Receiver pool is 1,000, Payer pool is 200, E equals 5, and a 2% price move is a 2% Receiver impact but a 10% Payer impact before funding and caps." />

<Note>
In words: `E` is not just a formula. It tells you how concentrated Payer risk is and why Payer funding can be attractive when Receiver demand is high.
</Note>

## Example

Suppose:

```text
Receiver pool = 1,000
Payer pool    = 200
E             = 5
```

If the reference asset falls by 2%, Receiver loses about 20 units and Payer receives those 20 units.

```text
Receiver: 1,000 -> 980
Payer:      200 -> 220
```

Receiver lost 2%. Payer gained 10%. The pool ratio turns the same price move into different percentage returns for each side.

## Summary

Receiver gets synthetic long exposure and pays funding. Payer backs that exposure, receives funding, and takes the opposite price risk. Both positions are pooled ERC-4626 shares, so users hold proportional claims on pool value rather than isolated bilateral contracts.
