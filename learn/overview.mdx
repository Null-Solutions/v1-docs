Null turns a total return swap into a pooled onchain market. The **Receiver** pool takes the return of an oracle-tracked asset. The **Payer** pool supplies the collateral that backs that exposure. Each side is fungible ERC-4626 shares.

A market is uniquely identified by three immutable dependencies:

```text
(collateral, oracle, frm)
```

- `collateral` — ERC-20 deposited into both pools
- `oracle` — tracked asset price (`1e36` scale)
- `frm` — funding-rate model

The market redistributes collateral it holds between the two pools. It does not lend, create debt, liquidate users, or mint an undercollateralized claim.

## Receiver

Receiver is the synthetic-long side. Deposit collateral, receive Receiver shares, own a proportional claim on that pool.

For an ordinary settled price move:

- price **up** → value moves Payer → Receiver
- price **down** → value moves Receiver → Payer

Funding is signed. Positive rate: Receiver pays Payer. Negative rate: Payer pays Receiver.

Receiver is synthetic exposure, not ownership of the tracked asset (no voting, dividends, or redemption rights unless the market rules explicitly account for them).

## Payer

Payer supplies the reserve that keeps Receiver fully collateralized and takes the opposite price transfer. Payer percentage returns can exceed the asset move when the Payer pool is smaller than Receiver — the same transfer is measured against a smaller base.

A Payer can keep that directional exposure or hedge externally. Null defines the onchain payoff; it does not run the hedge.

## Example (price only)

Ignore funding. Receiver 1,000, Payer 200, price falls 2%:

```text
Price PnL = 2% × 1,000 = 20

Receiver: 1,000 → 980   (−2%)
Payer:      200 → 220   (+10%)
```

In a real update, funding and price PnL are calculated from prepared state, netted, then applied as one solvency-bounded transfer. See [Settlement](/developers/settlement).

## Shares are pooled claims

Each share is a percentage of one pool's current assets — not a bilateral position with a private entry price. If you own 10% of a pool and no shares mint or burn, you still own 10% after settlement; the value of that claim changes with the pool.

The private-beta app labels enter/exit as Mint / Burn. Onchain these are ERC-4626 deposit / redeem.

## How value moves

Each settlement:

1. Read and validate the oracle price
2. Reconcile external collateral balance
3. Charge the annualized collateral fee
4. Query the FRM against prepared state
5. Net funding with price PnL; cap debit at `max(pool − MIN_POOL_ASSETS, 0)`
6. Store new timestamp and price

If the [circuit breaker](/security/circuit-breaker) fires, price PnL is skipped; funding still accrues and the new price becomes the next anchor.

## Why full collateralization matters

The net funding-and-PnL transfer cannot debit a pool below `MIN_POOL_ASSETS` if it starts above that floor. Reconciliation, collateral fees, and withdrawals are separate and can leave a pool below the floor. The accounting invariant is:

```text
receiverPool + payerPool + protocolFees == collateral.balanceOf(market)
```
