Every `deposit`, `mint`, `withdraw`, and `redeem` settles the market before changing pool shares or assets. Fee updates and fee sweeps also settle first. Settlement is interaction-driven; there is no public market `poke`.

`NullV1Market` prepares the state, queries the market's immutable funding-rate model, and delegates settlement math to `SettlementLib`.

## Execution order

The implementation follows this order:

1. Read the oracle price and reject zero.
2. Reconcile the market's external collateral balance.
3. Charge the annualized collateral fee.
4. Query the FRM against the prepared state.
5. Net signed funding with price PnL.
6. Cap and apply the net transfer.
7. Store the new timestamp and price.

In code terms:

```solidity
uint256 price = oracle.price();
if (price == 0) revert ZeroOraclePrice();

MarketState memory prepared =
    state.prepareUpdate(collateral.balanceOf(address(this)), collateralFee);
int256 fundingRate = frm.fundingRate(_marketParams(), prepared);
(MarketState memory updated, bool circuitBreakerFired) =
    prepared.finalizeUpdate(price, fundingRate);
```

## Price validation

Null oracles normalize prices to `1e36`. If `oracle.price()` reverts or returns zero, the entire triggering action reverts and no market state is persisted.

## Reconciliation

The market passes `collateral.balanceOf(address(this))` to `prepareUpdate`. Reconciliation first reserves as many recorded `protocolFees` as the external balance can cover, then compares the remainder with recorded Receiver and Payer assets.

External gains and losses are allocated pro rata across both pools. On a loss, any rounding remainder is deducted from the larger remaining pool first.

If both pools are empty, the remaining external balance is assigned to `protocolFees`. This avoids division by zero and prevents unassigned collateral from being credited to later depositors.

## Collateral fee

After reconciliation, the annualized fee is calculated independently for each pool:

```text
pool fee = pool balance * collateralFee / 10,000 * elapsed / 365 days
```

Each charge is capped at that pool's full balance and added to `protocolFees`. It is a fee on pool assets over time, not a share of measured collateral yield.

## FRM query and funding

The market calls:

```solidity
frm.fundingRate(
    NullV1MarketParams({
        collateral: address(collateral),
        oracle: address(oracle),
        frm: address(frm)
    }),
    prepared
);
```

The FRM receives the state after reconciliation and collateral fees. It returns a signed WAD-scaled APR: positive means Receiver pays Payer; negative means Payer pays Receiver.

For the standard imbalance FRM:

```text
f = mu * (cR - P) / (cR + P)
```

Funding accrues on prepared Receiver assets in either direction:

```text
funding amount = R * abs(f) / 1e18 * elapsed / 365 days
```

No funding amount accrues when time has not advanced, the rate is zero, or either pool is empty.

## Price settlement

Price PnL uses prepared Receiver assets and the previous stored price:

```text
receiver base notional = R * 1e36 / previous price
price PnL              = price delta * receiver base notional / 1e36
```

A price increase contributes a Payer-to-Receiver transfer; a decrease contributes a Receiver-to-Payer transfer. Market initialization reads and stores the first nonzero oracle price, so live markets begin with a price anchor.

## Circuit breaker

The allowed absolute price delta scales linearly with elapsed time:

```text
maxAllowedDelta = previousPrice * 700 * elapsed / (10_000 * 1 hour)
```

When `block.timestamp <= lastUpdate`, the circuit-breaker calculation uses one second of elapsed time. If the actual delta exceeds the limit, price PnL is skipped and `circuitBreakerFired` is true.

The update still accrues funding when time advanced and stores the new price as the next settlement anchor. It does not defer the skipped price PnL.

## Netted solvency bound

Funding and price settlement are netted before collateral moves between pools.

```text
net transfer into Receiver = price transfer from Payer to Receiver - funding from Receiver to Payer
```

In that expression, negative funding naturally increases the transfer into Receiver. The final debit is bounded by:

```text
settleable assets = max(pool assets - MIN_POOL_ASSETS, 0)
```

`MIN_POOL_ASSETS` is `1e6` raw collateral units. A positive net transfer is capped by Payer's settleable assets; a negative one is capped by Receiver's. The cap applies regardless of share supply and only to this net transfer. Reconciliation and collateral fees run first without the floor, so a prepared pool can already be at or below `MIN_POOL_ASSETS`; in that case it cannot be debited by funding or price PnL. Any unpaid remainder is not recorded as debt.

If either prepared pool is empty, `SettlementLib` skips both funding and price PnL for that update.

## Persistence and events

After settlement, the market stores the updated `MarketState` and emits `UpdateState`:

```solidity
event UpdateState(
    uint256 indexed lastUpdate,
    uint256 receiverPoolAssets,
    uint256 payerPoolAssets,
    uint256 protocolFees,
    uint256 price,
    bool circuitBreakerFired
);
```

Pool actions continue only after this state has been persisted.

## Integration implications

- Previews can become stale because execution updates the market first.
- Indexers should treat `UpdateState` as the canonical settlement checkpoint.
- FRM reads and simulations must use the post-reconciliation, post-collateral-fee state.
- Empty or one-sided markets skip both funding and price PnL.
- The circuit breaker skips price PnL, not funding or anchor advancement.
- Solvency is applied to the netted transfer, not to funding and price movement separately.
