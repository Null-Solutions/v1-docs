Each `NullV1Market` holds the collateral for its receiver and payer pools. The market owns settlement accounting; the pools own ERC-4626 share accounting.

## State

```solidity
function state() external view returns (
    uint256 lastUpdate,
    uint256 receiverPoolAssets,
    uint256 payerPoolAssets,
    uint256 protocolFees,
    uint256 price
);
```

- `lastUpdate` is set at initialization and after each completed state update.
- `receiverPoolAssets` and `payerPoolAssets` are denominated in collateral token units.
- `protocolFees` are collateral units reserved for the protocol owner.
- `price` is the last accepted `1e36`-scaled oracle price.

## Accessors

```solidity
function factory() external view returns (address);
function collateral() external view returns (IERC20);
function oracle() external view returns (INullV1Oracle);
function frm() external view returns (INullV1FundingRateModel);
function receiverPool() external view returns (INullV1Pool);
function payerPool() external view returns (INullV1Pool);
function entryFee() external view returns (uint16);
function exitFee() external view returns (uint16);
```

Fees are basis points. Entry and exit default to 25 bps and are capped at `250` (2.5%). They are charged on settleable-R notional. There is no other fee. Where a fee lands depends on the side that pays it: Receiver-side fees go to the Payer pool (or back to the Receiver pool while the Payer pool is at or below `MIN_POOL_ASSETS`), and Payer-side fees go to `protocolFees`. See [Fees](/protocol/fees).

## Settlement

State accrual is interaction-driven. There is no permissionless public “poke”: `updateState()` is callable only by the two pools. Every pool deposit or redemption settles first (the pools' only live entry points; `mint` and `withdraw` are disabled). `setFees` also settles before applying its change. `sweepFees` does not settle.

Settlement reconciles the market's actual collateral balance, obtains the signed WAD-scaled funding rate from `frm`, and settles funding and price PnL between pools. Positive funding means receivers pay payers; negative funding means payers pay receivers.

When both pools are above `MIN_POOL_ASSETS`, price PnL is skipped if the price moved by more than 20% (`MAX_ABS_CHANGE_BPS = 2000`) since the last settlement. The cap is flat and does not depend on elapsed time. Funding still settles and `UpdateState.circuitBreakerFired` is `true`. If either pool is at or below `MIN_POOL_ASSETS`, both price PnL and funding transfer are skipped and the flag is `false`; the new price and timestamp are still stored. Price PnL and funding are sized on the Receiver pool above the floor, and settlement transfers are capped so the debited pool retains `MIN_POOL_ASSETS` (`1e18` raw collateral units, one whole token of 18-decimal collateral).

## Owner operations

The protocol owner is the current `owner()` of the factory.

```solidity
function setFees(
    uint16 newEntryFee,
    uint16 newExitFee
) external;

function sweepFees() external returns (uint256 amount);
```

`setFees` settles the market, then checks each fee against its cap and stores both.

`sweepFees` transfers the `protocolFees` recorded at the last settlement to the protocol owner, and emits `CollectFees` only when the amount is nonzero. It does not settle the market, reads no oracle price, and emits no `UpdateState`. Collateral donated while both pools are empty is counted into `protocolFees` only by the next settlement (any deposit or redemption, including a zero-amount deposit), so it can be swept only after that.

## Events

```solidity
event UpdateState(
    uint256 indexed lastUpdate,
    uint256 receiverPoolAssets,
    uint256 payerPoolAssets,
    uint256 protocolFees,
    uint256 price,
    bool circuitBreakerFired
);

event SetFees(
    uint16 entryFee,
    uint16 exitFee
);

event CollectFees(uint256 fee);
```

## Errors

| Error | Condition |
|---|---|
| `NotProtocolOwner(address caller, address protocolOwner)` | A non-owner calls `setFees` or `sweepFees`. |
| `InvalidFee(uint256 fee, uint256 maxFee)` | A configured fee exceeds its cap. |
| `NotPool(address caller, address receiverPool, address payerPool)` | A non-pool caller invokes a pool-only callback. |
| `NotDeployedMarket()` | The factory registry no longer maps this market's `(collateral, oracle, frm)` tuple to this market. |
| `ZeroOraclePrice()` | The oracle returns zero during initialization or settlement. |
| `ZeroCollateral()` / `ZeroOracle()` | Initialization receives a zero dependency. |
