Null V1 has two routers with the same market-operation signatures but different oracle fee models.

## Choose the correct router

### `NullV1Router`

`NullV1Router` is stateless, ownerless, and nonpayable. It never holds or forwards ETH. When `updateData` is nonempty it calls:

```solidity
INullV1UpdatableOracle(address(oracle)).update(updateData);
```

Use it for fee-less updatable oracles such as the Null V1 Chainlink implementation. Pass an empty array to skip the update. Native-fee oracles are unsupported.

### `NullV1PayableRouter`

`NullV1PayableRouter` is for native-fee oracles such as Pyth. It has an owner and a payable `receive()` function. Pre-fund the router with ETH; when `updateData` is nonempty it calls `getUpdateFee(updateData)` and forwards exactly that amount to `update`.

User calls are not payable—the fee comes from the router's existing balance.

```solidity
constructor(address newOwner);

function withdrawEth(
    address to,
    uint256 amount
) external;

event WithdrawEth(address indexed to, uint256 amount);
```

Only the owner may withdraw. `withdrawEth` reverts with `ZeroAddress()`, `InsufficientUpdateFeeBalance(uint256 balance, uint256 required)`, or `TransferFailed()` as applicable, plus OpenZeppelin's ownership error for an unauthorized caller.

## Shared market operations

### Create

```solidity
function createMarket(
    INullV1Factory factory,
    IERC20 collateral,
    INullV1Oracle oracle,
    INullV1FundingRateModel frm,
    bytes[] calldata updateData
) external returns (INullV1Market market);
```

The router optionally updates the oracle, then calls `factory.createMarket(collateral, oracle, frm)`. The router does not verify that the supplied factory is canonical. The FRM must be enabled on that factory.

### Deposit

```solidity
function depositMarket(
    INullV1Market market,
    uint256 receiverAssets,
    uint256 payerAssets,
    uint256 minReceiverShares,
    uint256 minPayerShares,
    uint256 deadline,
    bytes[] calldata updateData
) external returns (
    uint256 receiverShares,
    uint256 payerShares
);
```

Set either asset amount to zero to skip that side. Shares are minted to `msg.sender`. For plain ERC-20 collateral, asset amounts are collateral units. If market collateral is detected as ERC-4626, asset amounts are units of that vault's underlying; the router pulls the underlying and wraps it before depositing. Approve the router for the token it will pull.

### Redeem

```solidity
function redeemMarket(
    INullV1Market market,
    uint256 receiverShares,
    uint256 payerShares,
    uint256 minReceiverAssets,
    uint256 minPayerAssets,
    uint256 deadline,
    bytes[] calldata updateData
) external returns (
    uint256 receiverAssets,
    uint256 payerAssets
);
```

Set either share amount to zero to skip that side. Approve the router to spend the relevant pool shares. Plain collateral is returned directly to `msg.sender`; ERC-4626 collateral is redeemed and its underlying is returned. Minimum-asset checks apply to the amount the caller actually receives.

## Update order and errors

For deposits and redemptions the router checks the deadline, applies a nonempty oracle update, and then calls the pools. Pool execution performs market settlement.

Both routers define:

| Error | Condition |
|---|---|
| `TransactionTooOld(uint256 deadline)` | `block.timestamp > deadline`. |
| `SlippageReceiverShares(uint256 expected, uint256 actual)` | Receiver shares are below the minimum. |
| `SlippagePayerShares(uint256 expected, uint256 actual)` | Payer shares are below the minimum. |
| `SlippageReceiverAssets(uint256 expected, uint256 actual)` | Receiver assets are below the minimum. |
| `SlippagePayerAssets(uint256 expected, uint256 actual)` | Payer assets are below the minimum. |

The payable router additionally defines `InsufficientUpdateFeeBalance(uint256 balance, uint256 required)`.
