Every market deploys two `NullV1Pool` clones. They implement ERC-4626 while delegating collateral custody and settlement accounting to their market.

## Kind and naming

```solidity
enum NullV1PoolKind {
    Receiver, // 0
    Payer     // 1
}

function market() external view returns (INullV1Market);
function poolKind() external view returns (NullV1PoolKind);
```

Names and symbols come from the market oracle:

| Kind | Name | Symbol |
|---|---|---|
| `Receiver` | `<baseName> Receiver Share` | `r<baseSymbol>` |
| `Payer` | `<baseName> Payer Share` | `p<baseSymbol>` |

An empty oracle base name falls back to `Base`; an empty base symbol falls back to `BASE`.

## ERC-4626 accounting

```solidity
function totalAssets() public view returns (uint256);
```

`totalAssets()` reads the corresponding `receiverPool` or `payerPool` amount from the market's last settled state. The value is denominated in market collateral units and does not itself trigger settlement.

The pool's decimals offset is `10`. OpenZeppelin ERC-4626 therefore reports share decimals as `collateral.decimals() + 10` and includes `10^10` virtual shares in conversion math. Use ERC-4626 conversion and preview functions; do not assume assets and shares use the same decimals.

## Entry points

```solidity
function deposit(
    uint256 assets,
    address receiver
) public returns (uint256 shares);

function mint(
    uint256 shares,
    address receiver
) public returns (uint256 assets);

function withdraw(
    uint256 assets,
    address receiver,
    address owner
) public returns (uint256 shares);

function redeem(
    uint256 shares,
    address receiver,
    address owner
) public returns (uint256 assets);
```

Before conversion, each entry point locks the market's reentrancy guard and calls `market.updateState()`. Deposits transfer collateral directly from the caller to the market; withdrawals are paid by the market. If the caller redeems or withdraws another owner's shares, the owner must approve the caller.

Entry fees are included in the `assets` paid by depositors and excluded from assets converted into shares. Exit fees are charged in addition to withdrawn assets or deducted from redeemed assets. Both accrue to `state.protocolFees`.

## Previews

```solidity
function previewDeposit(uint256 assets) public view returns (uint256 shares);
function previewMint(uint256 shares) public view returns (uint256 assets);
function previewWithdraw(uint256 assets) public view returns (uint256 shares);
function previewRedeem(uint256 shares) public view returns (uint256 assets);
```

These functions include entry or exit fees and use the market's **last settled state**. Execution settles funding, collateral fees, balance changes, and price PnL first, so a stale market can produce materially different results. This is an accepted deviation from strict ERC-4626 preview semantics.

<Warning>
Use `NullV1Lens.previewMarket` for a settlement-accurate state projection, then enforce `minReceiverShares`, `minPayerShares`, `minReceiverAssets`, or `minPayerAssets` through the appropriate router.
</Warning>

## Max functions

```solidity
function maxDeposit(address) public view returns (uint256);  // type(uint256).max
function maxMint(address) public view returns (uint256);     // type(uint256).max
function maxWithdraw(address owner) public view returns (uint256);
function maxRedeem(address owner) public view returns (uint256);
```

Pools inherit the OpenZeppelin v5 defaults without overrides:

- `maxDeposit` and `maxMint` always return `type(uint256).max`. They do not reflect wallet balances, market state, or any protocol cap — do not use them to size deposit inputs.
- `maxRedeem(owner)` returns `balanceOf(owner)`.
- `maxWithdraw(owner)` returns `previewRedeem(balanceOf(owner))`, so it is net of the exit fee. Like every view, it is a snapshot of the last settled state; after execution settles the market, `withdraw(maxWithdraw(owner))` can require more shares than the owner holds and revert. Prefer `redeem` with the full share balance for a full exit.

Pools emit the standard ERC-20 `Transfer` and ERC-4626 `Deposit` and `Withdraw` events.
