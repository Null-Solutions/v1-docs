Null V1 supports two Chainlink Data Streams report schemas:

- `NullV1ChainlinkOracleV3` for continuously traded crypto feeds
- `NullV1ChainlinkOracleV11` for RWA feeds with regular, extended, and overnight
  sessions

Both verify signed reports through the configured Chainlink verifier proxy,
store the accepted report, and normalize its price to `1e36`.

## V3 crypto feeds

V3 uses one feed ID. It reads the report's `price` and
`observationsTimestamp`. An update must:

- use report schema version 3
- match the configured feed ID
- contain a positive price
- be strictly newer than the stored report, unless it has the same timestamp
- have an observation timestamp no more than 60 seconds old and not in the
  future

A report with the same timestamp is ignored. An older report reverts.

The display key is `keccak256("CHAINLINK_DATA_STREAMS_V3")`.

## V11 RWA and session feeds

V11 is configured with three distinct feed IDs. `priceId()` returns the regular
feed ID; `extendedPriceId()` and `overnightPriceId()` expose the other two.

The report's own `marketStatus` selects the only feed accepted for that report:

- `2`: regular feed
- `1` or `3`: extended feed (pre-market or post-market)
- `4`: overnight feed
- any other value: no active feed; the report is rejected

The oracle reads `mid` as the price and converts `lastSeenTimestampNs` to whole
seconds. The report must use schema version 11, identify one of the configured
feeds, identify the feed selected by its status, carry a positive price, and
have a timestamp within 60 seconds before or after the block timestamp.

<Note>
  Session validation is report-driven. The contract does not calculate exchange
  hours or independently determine which session should be open.
</Note>

The display key is `keccak256("CHAINLINK_DATA_STREAMS_V11")`.

## Nonpayable, fee-zero routing

Both implementations use the nonpayable `INullV1UpdatableOracle` interface:

```solidity
uint256 fee = oracle.getUpdateFee(updateData); // 0
oracle.update(updateData);
uint256 currentPrice = oracle.price();
```

<Note>
  Use the stateless `NullV1Router` for Chainlink. It calls the nonpayable
  `update(updateData)` and forwards no native currency. Do not use the payable
  Pyth router as the normal Chainlink path.
</Note>

`updateData` must contain at least one signed report. Each submitted report is
verified in sequence.

## Price normalization

The configured `priceDecimals` must be at most 36. V3 scales `price`, and V11
scales `mid`, with:

```text
normalizedPrice = reportPrice * 10^(36 - priceDecimals)
```

## Staleness and escape behavior

For both schemas, `price()` normally accepts a stored timestamp up to 60
seconds old. It reverts when the age is greater than 60 seconds but less than
10 days. At exactly 10 days old, and afterward, it returns the stored positive
price through the emergency escape path.

The read path also tolerates a stored timestamp up to 60 seconds in the future.
V3 never accepts a future timestamp during update; V11 accepts one up to 60
seconds ahead.

## Creation

```solidity
INullV1Oracle cryptoOracle = factory.createOracleV3(
    feedId,
    priceDecimals,
    baseName,
    baseSymbol,
    quoteName,
    quoteSymbol
);

INullV1Oracle rwaOracle = factory.createOracleV11(
    regularFeedId,
    extendedFeedId,
    overnightFeedId,
    priceDecimals,
    baseName,
    baseSymbol,
    quoteName,
    quoteSymbol
);
```
