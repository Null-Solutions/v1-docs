The `NullV1UniswapV3Oracle` reads price data directly from an on-chain Uniswap V3 pool's time-weighted average price (TWAP). Because all pricing data lives on-chain, there is no off-chain API to query, no signed update bytes to submit, and no update fee to pay. You pass an empty array (`[]`) as `updateData` to the router, and the oracle reads the current TWAP automatically when `price()` is called. This makes it the simplest oracle type to integrate — if your target market already has a Uniswap V3 pool with adequate liquidity and observation history, you can deploy and use this oracle immediately.

## When to Use This Oracle

The Uniswap V3 TWAP oracle is the natural choice when:

- Your market's base asset is an ERC-20 token with an established Uniswap V3 pool.
- You want pricing that is entirely on-chain and requires no external services or signed reports.
- You are building on a chain where Uniswap V3 is the primary liquidity venue for your token pair.

It is **not** suitable for real-world assets (equities, commodities, FX) that have no meaningful on-chain Uniswap V3 representation, nor for assets where TWAP manipulation risk is a concern due to thin liquidity.

<Warning>
  TWAP oracles can be manipulated on pools with low liquidity or short TWAP windows. Before deploying this oracle for a production market, verify that the underlying Uniswap V3 pool has sufficient liquidity depth and that the TWAP window is long enough to resist single-block manipulation. A longer TWAP window increases manipulation cost but introduces price lag.
</Warning>

## How It Works

The oracle calls the Uniswap V3 pool's `observe()` function to retrieve cumulative tick data at two points in time separated by the configured TWAP window. It converts the resulting geometric mean tick to a price and normalizes it to the protocol's 1e36 scale.

The TWAP window is set at deployment time. Longer windows smooth out short-term volatility and increase manipulation cost; shorter windows track the spot price more closely.

## Price Normalization

Uniswap V3 pools express prices as Q64.96 fixed-point square roots of token ratios. The oracle converts this representation to a standard decimal price, then scales it to 1e36, accounting for the decimal difference between the two tokens in the pair:

```
normalizedPrice = uniswapSqrtPriceX96^2 * 10^(36 + baseDecimals - quoteDecimals) / 2^192
```

The result is the same 1e36-scaled price that all other Null V1 oracles return, so pool contracts interact with this oracle identically to Pyth or Chainlink.

## Using with the Router

Because this oracle is push-based (it reads live on-chain state), no update step is needed. Pass an empty `updateData` array when calling the router:

```solidity
// No updateData needed — pass an empty array
bytes[] memory updateData = new bytes[](0);

router.depositMarket{value: depositAmount}(
    marketId,
    depositAmount,
    minShares,
    updateData   // empty — Uniswap V3 oracle reads on-chain directly
);
```

<Note>
  The router detects that no update bytes are present and skips the `oracle.update()` call. The oracle's `price()` function reads the TWAP from the pool at the time of the transaction, so the price is always current as of the block being executed.
</Note>

## Reading the Price Directly

For testing or off-chain simulation, you can read the oracle price directly without the router:

```solidity
// Returns the TWAP price scaled to 1e36
uint256 currentPrice = oracle.price();
```

No preparation is required — the call executes entirely within the EVM using on-chain pool state.

## Interface

`NullV1UniswapV3Oracle` implements only `INullV1Oracle` (not `INullV1UpdatableOracle`, since no update mechanism is needed):

```solidity
interface INullV1Oracle {
    function price() external view returns (uint256);
    function displayName() external view returns (bytes32);
    function oracleName() external view returns (string memory);
    function baseName() external view returns (string memory);
    function baseSymbol() external view returns (string memory);
    function quoteName() external view returns (string memory);
    function quoteSymbol() external view returns (string memory);
}
```

## Deployment

Deploy through `NullV1UniswapV3Factory`. You supply the address of the Uniswap V3 pool and the desired TWAP window in seconds:

```solidity
address oracle = NullV1UniswapV3Factory(factory).deploy(
    poolAddress,   // address — the Uniswap V3 pool to read TWAP from
    twapWindow,    // uint32  — TWAP observation window in seconds (e.g. 1800 for 30 min)
    baseName,      // string  — e.g. "Wrapped Bitcoin"
    baseSymbol,    // string  — e.g. "WBTC"
    quoteName,     // string  — e.g. "USD Coin"
    quoteSymbol    // string  — e.g. "USDC"
);
```

<Tip>
  Before deploying, verify that the pool's observation cardinality is large enough to support your chosen TWAP window. Call `pool.increaseObservationCardinalityNext(n)` if needed to extend the observation buffer. A pool that lacks sufficient history will cause `price()` to revert until the buffer is populated.
</Tip>
