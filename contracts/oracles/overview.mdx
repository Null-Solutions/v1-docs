Null V1 uses a modular oracle system where every price feed implements a common interface, `INullV1Oracle`. This shared surface lets the protocol read prices uniformly regardless of the underlying data source, whether that is an updatable service like Pyth or Chainlink Data Streams, an onchain Uniswap V3 TWAP, or a stateless feed derived from `block.basefee`. Oracles that require offchain price updates additionally implement `INullV1UpdatableOracle`, which adds a standard `update()` entry point so the router can hydrate the feed before any pool operation.

<Note>
For oracle selection guidance, read [Null V1 oracle types and integration guide](/markets/oracles). This page is the oracle interface reference.
</Note>

## Price Scale

All oracles return prices scaled to **1e36**. A price of $3,000 for `AAPL/USD` is represented as `3000 * 1e36`. This fixed scale eliminates per-feed decimal handling in the core protocol — your integration always works with the same magnitude regardless of oracle type.

## The updateData Flow

For updatable oracles such as Pyth and Chainlink Data Streams, price data must be fetched offchain and submitted onchain before the pool reads the price. The sequence is:

1. **Fetch** signed update bytes from the relevant off-chain API (Pyth Hermes or Chainlink Data Streams).
2. **Pass** those bytes as `updateData` in your call to `router.depositMarket(...)` or `router.redeemMarket(...)`.
3. **The router** calls `oracle.update{value: fee}(updateData)` automatically before executing the pool operation.
4. **The oracle** stores the validated price, and the pool reads it via `oracle.price()`.

For onchain or stateless oracles such as Uniswap V3 TWAP and Base Fee, no offchain data is needed. Pass an empty array (`[]`) as `updateData` and the router skips the update step entirely.

<Note>
  The current router handles update fee payment from its own ETH balance. Ensure
  the deployed router is funded before relying on fee-charging oracle updates.
</Note>

## INullV1Oracle Interface

Every oracle in Null V1 implements `INullV1Oracle`. These functions give you the current price and descriptive metadata used by UIs and indexers.

```solidity
interface INullV1Oracle {
    function price() external view returns (uint256);
    function displayName() external view returns (bytes32);
    function oracleName() external view returns (string memory);
    function baseName() external view returns (string memory);
    function baseSymbol() external view returns (string memory);
    function quoteName() external view returns (string memory);
    function quoteSymbol() external view returns (string memory);
}
```

<ParamField path="price()" type="uint256">
  Returns the current price of the base asset in the quote asset, scaled to **1e36**. For example, `3000 * 1e36` represents $3,000 per unit.
</ParamField>

<ParamField path="displayName()" type="bytes32">
  A keccak256-hashed key identifying the oracle type (e.g. `keccak256("PYTH_CORE_PULL")`). Used by front-ends and indexers to render the correct oracle label without string comparisons.
</ParamField>

<ParamField path="oracleName()" type="string">
  A human-readable name for this oracle instance, such as `"NullV1PythOracle"`.
</ParamField>

<ParamField path="baseName()" type="string">
  Full name of the base asset (e.g. `"Apple Inc."`). Consumed by UIs and indexers to display asset metadata.
</ParamField>

<ParamField path="baseSymbol()" type="string">
  Ticker symbol of the base asset (e.g. `"AAPL"`). Used for display and routing in front-end integrations.
</ParamField>

<ParamField path="quoteName()" type="string">
  Full name of the quote asset (e.g. `"US Dollar"`).
</ParamField>

<ParamField path="quoteSymbol()" type="string">
  Ticker symbol of the quote asset (e.g. `"USD"`).
</ParamField>

<Note>
  Oracle metadata (`baseName`, `baseSymbol`, `quoteName`, `quoteSymbol`) is informational only. The protocol does not use these fields for any on-chain logic — they exist purely so UIs and indexers can display accurate asset information without maintaining a separate registry.
</Note>

## INullV1UpdatableOracle Interface

Pull-based oracles (Pyth and Chainlink Data Streams) additionally implement `INullV1UpdatableOracle`. This interface standardizes how the router submits off-chain price reports before reading a price.

```solidity
interface INullV1UpdatableOracle {
    function update(bytes[] calldata updateData) external payable;
    function getUpdateFee(bytes[] calldata updateData) external view returns (uint256);
    function priceId() external view returns (bytes32);
}
```

<ParamField path="update(updateData)" type="bytes[] calldata" required>
  Submits off-chain signed price report bytes to the oracle. The oracle validates the data, checks for staleness, and stores the new price. Must be called (by the router) before `price()` on any block where fresh data is required. Send ETH equal to `getUpdateFee(updateData)` with this call.
</ParamField>

<ParamField path="getUpdateFee(updateData)" type="bytes[] calldata" required>
  Returns the amount of ETH (in wei) required to submit the given `updateData`. For Pyth, this delegates to the Pyth contract's fee calculation. For Chainlink Data Streams, this always returns `0`.
</ParamField>

<ParamField path="priceId()" type="bytes32">
  The feed identifier registered at oracle deployment. For Pyth this is the Pyth price feed ID; for Chainlink this is the primary (regular-session) feed ID. Used by off-chain tooling to know which feed to query.
</ParamField>

## Choosing an Oracle

| Oracle | Data Source | updateData Required | Update Fee | Best For |
|--------|------------|---------------------|------------|----------|
| Pyth | Pyth Hermes API | Yes | Small ETH fee | Crypto and RWA assets on Pyth |
| Chainlink Data Streams | Chainlink API | Yes | Free | US equity RWA markets |
| Uniswap V3 TWAP | On-chain pool | No (`[]`) | None | ERC-20 token markets |
| Base Fee | `block.basefee` | No (`[]`) | None | Gas-price-indexed markets |
