`NullV1MorphoRouter` is a stateless helper that opens and closes leveraged Null positions on Morpho Blue. It holds no balances between transactions and keeps no position state of its own. Morpho owns the debt and collateral records, the Null pools own the underlying exposure, and the router simply sequences the two inside Morpho's flash loan and callback flow.

One deployment serves both books. A long borrows the loan token against Receiver pool shares. A short borrows Receiver shares against the market collateral, `nmUSDC`. Before any flow that borrows or withdraws collateral, the caller must authorize the router on Morpho with `setAuthorization(router, true)`. The one exception is a long opened with zero debt, which only supplies collateral.

Every function takes a `deadline` and reverts with `TransactionTooOld` once `block.timestamp` passes it, and an `updateData` array carrying any oracle reports the Null market needs in order to settle before trading.

## Long functions

`open` deposits `equity` plus `debt` of the loan token into the Receiver pool, supplies the resulting shares to Morpho, and borrows `debt` to repay the flash loan. It returns the total collateral shares posted. `minCollateralShares` is the caller's floor on that return value.

```solidity
function open(
    INullV1Market market,
    MarketParams calldata marketParams,
    uint256 equity,
    uint256 debt,
    uint256 minCollateralShares,
    uint256 deadline,
    bytes[] calldata updateData
) external returns (uint256 collateralShares);

function openWithPermit2(..., Permit2Signature calldata permit) external returns (uint256 collateralShares);

function close(
    INullV1Market market,
    MarketParams calldata marketParams,
    uint256 minAssetsOut,
    uint256 deadline,
    bytes[] calldata updateData
) external returns (uint256 assetsOut);
```

`openWithPermit2` behaves exactly like `open`, except the equity is pulled through Permit2 rather than an ERC-20 allowance. The abbreviated signature above takes the same leading arguments as `open`, followed by the permit. `close` unwinds the caller's whole position on the book and returns the loan token left after repayment, which must meet `minAssetsOut`.

For a long, `marketParams.collateralToken` must be the Receiver pool. `loanToken` must be the underlying of the market collateral, USDC in the current stack, or the collateral itself when that collateral is not a vault.

## Short functions

`openShort` posts `nmUSDC` collateral, borrows `shortShares` of the Receiver pool from Morpho, and sells them through the Null market. It returns the collateral posted, which must meet `minCollateral`. `closeShort` returns the assets left after the short is covered.

```solidity
function openShort(
    INullV1Market market,
    MarketParams calldata marketParams,
    uint256 equity,
    uint256 shortShares,
    uint256 minCollateral,
    uint256 deadline,
    bytes[] calldata updateData
) external returns (uint256 collateral);

function openShortWithPermit2(..., Permit2Signature calldata permit) external returns (uint256 collateral);

function closeShort(
    INullV1Market market,
    MarketParams calldata marketParams,
    uint256 minAssetsOut,
    uint256 deadline,
    bytes[] calldata updateData
) external returns (uint256 assetsOut);
```

`closeShort` deserves a note, because it does not work the way a manual cover would. The router mints the Receiver shares it owes inside Morpho's repay callback, depositing collateral into the pool at that moment. The short book therefore needs no idle Receiver shares for an exit to succeed.

For a short, `marketParams.loanToken` must be the Receiver pool and `collateralToken` must be `market.collateral()`.

## Events

Each completed flow emits one event, indexed by user and by market, so indexers can rebuild a position history from logs alone:

```solidity
event LoopOpened(address indexed user, INullV1Market indexed market, uint256 equity, uint256 debt, uint256 collateralShares);
event LoopClosed(address indexed user, INullV1Market indexed market, uint256 repaidAssets, uint256 collateralShares, uint256 assetsOut);
event ShortOpened(address indexed user, INullV1Market indexed market, uint256 equity, uint256 shortShares, uint256 collateral);
event ShortClosed(address indexed user, INullV1Market indexed market, uint256 repaidShares, uint256 collateral, uint256 assetsOut);
```

## Errors

The router fails early and specifically. Most integrator bugs surface as one of the first four errors below, long before any funds move.

| Error | When it reverts |
| --- | --- |
| `NotMorpho` | A callback arrives from an address that is not the Morpho singleton. |
| `UnexpectedCallback` | Callback data does not match the action currently in flight. |
| `MarketMismatch` | The token pair is not the long or short shape this Null market requires. |
| `ZeroEquity` | `equity` is zero on an open. |
| `ZeroShort` | `shortShares` is zero on a short open. |
| `NoPosition` | A close is attempted with zero Morpho collateral on that book. |
| `TransactionTooOld` | `block.timestamp` is past the supplied `deadline`. This error comes from the shared base contract. |

Separately, the router reverts with slippage errors whenever Receiver shares, posted collateral, or returned assets come in below the floor the caller supplied. Treat those as pricing failures rather than contract failures, and re-quote before resubmitting.
